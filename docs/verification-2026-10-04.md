## 已复现并修复

| 场景 | 修复后的行为 |
|---|---|
| 翻译后客户语言自动识别改变，再点发送 | 保留已准备译文的目标，直接发送，不再翻译译文 |
| 用户手动改目标语言 | 从保留的原稿翻译到新目标 |
| 异步粘贴、框架回声、零宽字符或显示空格变化 | 保留译文身份，防止再次翻译 |
| 用户在请求或回填期间真正编辑 | 旧结果失效，不覆盖新草稿、不自动发送 |
| 只写入部分译文、换行／空行丢失、AI 回填失败 | 显示持续错误，保留原稿，提供重试／恢复原稿；拦截残缺文本发送 |
| 请求中手动改语言或更新设置 | 丢弃旧结果并说明原因 |
| 错误提示快速消失或遮挡工具栏 | 提示独立显示，可重试、关闭；语言和 AI 按钮仍可操作 |
| 翻译中重复点击发送 | 不重复请求，提示等待完成后发送 |
| 气泡 DOM 重建 | 复用消息译文；引擎配置变化后失效 |
| 扩展重载、连接失效 | 接管旧实例；失效提示刷新并停止重复请求 |
| 模型查询／测试晚到，配置已改或已取消 | 丢弃过期响应；重复点击仅一次请求 |
| 设置保存失败或保存中取消 | 显示失败；串行保存；保存期间保持界面与已写入配置一致 |
| 用户已填写旧模型，被自动替换 | 保留模型；真实模型目录与内置候选明确区分 |
| 数字、电话、金额、时间、表情、网址、邮箱、明确型号、OK | 不请求翻译接口；普通句子仍翻译 |

## 验证证据

`npm test` 全部通过：原有扩展／聊天工具回归，60 个输入场景、33 个草稿生命周期场景、7 个设置请求场景，共 100 个专项场景。

Chromium 使用模拟消息和接口，实际操作结果：

- 异步粘贴延迟 60 ms、接口延迟 80 ms：第一次点发送准备译文，第二次点击发送，`calls=1, sends=1`。
- 数字、独立网址、表情分别点击发送：`calls=0, sends=3`。
- HTTP 401 后等待 1.9 s：原稿未变，`sends=0`；错误仍显示，AI 按钮可点击，工具控件未被遮挡。
- 编辑器只写入 `Line` 并触发自身 input：显示恢复原稿；恢复后 `calls=1, sends=0, draft=中文原稿`。
- `node --check` 检查 content、popup、background；`git diff --check` 无空白错误。

## 审查取舍与验证范围

- DeepSeek 第一轮的“缺少项目文件”源于审查快照复制遗漏，已撤销，不是项目缺陷。
- 最终复核的“取消后没有提示”来自其插桩包装器丢掉 `reason` 参数，修正探针后立即和稍后的提示都正确。较新 happy-dom 把 `InputEvent.data:null` 变成空字符串的差异也已复现，补上空回声兼容并新增回归。
- 没有采用“拉丁文字一律不翻译”建议，会破坏英语→西语等正常需求。本地检测可靠时跳过同目标文本或翻译可靠识别的外语；英语默认下无法可靠识别的短拉丁文本保持原文。
- 身份比较允许显示差异；写入确认另用严格比较，防止换行丢失被当成成功。
- 输入框已被替换时，旧请求不写进新元素；重新请求会经过后台缓存／并发合并。消息调用次数不能直接视为收费 API 次数。
- 不把名为 `Menu` 的任意按钮当作发送按钮，避免干扰附件、菜单、录音。真实 WhatsApp DOM 兼容性仍需登录页面确认。
- 本轮没有向真实联系人发送消息，也没有验证实际账号的翻译额度／模型权限。模拟编辑器覆盖确定机制，不能保证真实 WhatsApp 所有版本的行为。
